# Agent instructions

This file is the repo law for agents and contributors. `VISION.md` says what the product is for. Read it before you design anything. It holds the commands, the validation rules, the architecture constraints, and the stop rules. The fence (types, lint, hooks, CI) enforces most of it. Fence wins over prose.

nostakes is a web app where groups of friends play poker online, at most 9 players per room. Chip accounting must be exactly right.

## Packages

- `@nostakes/engine` (`packages/engine`): pure no-limit hold'em rules
- `@nostakes/ledger` (`packages/ledger`): buy-ins, cash-outs, and settle-up transfers
- `@nostakes/room` (`packages/room`): one poker night as a pure reducer over the engine, the ledger, and the shuffle: members, host, seats, clocks, the queue at the end of a hand, views, and redaction. A member who leaves the room keeps a working pass and a per-person settlement. The view lists them in `departed` with their name and face until they join again, marks their seat `leavingRoom` while it plays out the hand, and still names them in `you` on their own device. The room takes `RoomCodeSchema` from `@nostakes/protocol`, the one source for a room code's format. In a room whose `shuffle` setting is `Checked` (the default for a new room), `src/sealing.ts` seals each hand (`SealDue`, `SealHand`, `HandSealed`) and deals it from the sealed beacon round (`SealedDealDue`, `DealSealed`), verifying the round's signature against the chain in `RoomOpened`; `src/openings.ts` sends every shown card's opening to exactly its audience; `src/witness.ts` turns what one device saw into `judgeHand`'s input. Once a seal binds, the sealed seats are frozen until the hand is dealt, and the end-of-hand queue never runs in a batch that deals hole cards (`QueueDue`, `RunQueue`). A checked hand costs about 18 ms of BLS checking in `decide`, so the generic room properties make one room in twenty checked. `packages/shuffle/DESIGN.md` section 12 records the design as built.
- `@nostakes/shuffle` (`packages/shuffle`): the provably fair shuffle, pure, used by the room for checked hands. It seals two decks per hand as Merkle trees of salted cards, orders the deal from a drand quicknet beacon round named in the seal, checks drand's BLS signature, judges from a device's own clock whether the seal arrived before its round, lists sealed hands with no deal, and gives one verdict per hand (`judgeHand`). `DESIGN.md` there holds the threat model, the margins, and the cheat table.
- `@nostakes/avatar` (`packages/avatar`): the players' faces, pure. An avatar is a Schema of parts and colours (species, coat, marking, eyes, mouth, cheeks, accessory, accent, backdrop) that encodes to an 11-character code inside the room's 512-character avatar string (`codeFor`, `AvatarFromCode`). `avatarFor` reads any stored string and falls back to `DEFAULT_AVATAR`, so an old emoji or garbage still draws a face. `render(avatar, { expression, size })` returns an SVG string for six table expressions: `Resting`, `LookingDown`, `Thinking`, `Happy`, `Gutted`, and `Folded`. `randomAvatar(seed)` is the shuffle. The art is original and drawn in code in `src/draw.ts`.
- `@nostakes/protocol` (`packages/protocol`): the JSON frames between a room's clients and its server, the room pass, and the wire limits. It is generic over a room core's schemas, so it never imports the room, and it does no I/O.
- `@nostakes/client` (`packages/client`): the headless room client. It holds one connection, resumes after a drop without missing or repeating an event, resends unanswered commands with their ids, and exposes the view, the applied events, the connection state, and presence. Its `updates` stream gives each view together with the events that produced it and the sequence number it reflects, in the order the room applied them, so a UI never shows a view ahead of the events that led to it. The web app takes its view and its events only from `updates`. Like `protocol` it is generic over a core's schemas and never imports the room. It reads no `window` or `document`. While live it is owed a `Pong` for each `Ping` and a `Reply` for each `Command`. The connection tells the machine as each such frame leaves the throttle, and the machine arms one deadline per frame, `ANSWER_LIMIT_MS` from that moment. A ping whose pong is late marks the line overdue and starts a grace of `OVERDUE_GRACE_MS`, counted from when the machine notices, so a pong that reached the socket while the app was busy still counts. If it is still unanswered when the grace ends, the client drops the socket as `Unanswered`. A late reply is not proof that nobody hears the client, because a slow room delays replies while the runtime still answers pings, so a late reply sends one ping probe and lists the command in `waitingForTable` instead of dropping. The probe's own pong deadline decides whether the line is heard. A command still unanswered `REPLY_LAST_RESORT_MS` after it left drops the connection once, in case the socket is half-broken in a way pings do not show. Its unit and model tests use a fake socket and the test clock. Its tests against the real server live in `apps/room-server/test/client-room.test.ts`, because a package may not import app code.
- `@nostakes/room-server` (`apps/room-server`): the Cloudflare Worker and one Durable Object per room, declared with Alchemy. It hosts any core that satisfies `HostedRoom` in `src/hosted-room.ts`. `src/poker-room.ts` adapts `@nostakes/room` to that port for one drand chain (`pokerRoomOn`), and `src/poker-room-object.ts` is the production object. Before a sealed deal the alarm asks the `Beacon` service in `src/beacon.ts` for the round's signature: the live layer asks drand's relays until 15 s after the round was due, and the test layer (`test/fixtures/test-beacon.ts`) signs rounds with its own key inside workerd, is down on every 29th round, and never touches the network. `src/serve-rooms.ts` is the Worker body. `src/worker.ts` wraps it for local development and tests, with allowed origins read from the `ALLOWED_ORIGINS` config. `src/site-worker.ts` wraps it for nostakes.club: one Worker serves the built web app as static assets and runs the room routes first for `/rooms` and `/rooms/*`, so the page and the server share one origin, the stage's own. It also runs first for `/`, `/r/*`, and `/preview/*` through `src/site-pages.ts`, because chat apps read link previews from the HTML without running the app: `/` serves `index.html` and a room link serves `invite.html`, each with `https://nostakes.club` in its tags replaced by the request's own origin, and `/preview/*` answers byte ranges with 206, which the asset layer does not and iOS needs to play the preview clip. `scripts/production.run.ts` declares that Worker with Alchemy for the stages `production` (nostakes.club) and `preview` (preview.nostakes.club), with Alchemy's state in a Cloudflare state store named `nostakes-state`. Cloudflare rate limits in `src/address-limits.ts` cap rooms, joins, and socket upgrades per address. A room deletes its storage `ROOM_RETENTION_MS`, 30 days, after its last event. Its tests drive a toy core and the real room through real WebSocket clients on local workerd. Seeded bots in `test/fixtures/bot.ts` play whole nights, and `test/fixtures/night-checks.ts` checks every frame they received against the stored log. Every bot device also judges every hand it saw with `judgeHand` (`test/fixtures/fair-checks.ts`), checks a "beacon unavailable" deal against the test relay itself, and fails the night on a failed verdict, a card shown without its opening, or a sealed hand never dealt. Each night splits its bots by seed into raw socket bots, which also break the protocol on purpose, and client bots in `test/fixtures/client-bot.ts`, which run `@nostakes/client` over the live WebSocket transport and play from its view. A client bot's wire (`test/fixtures/client-wire.ts`) can be closed from the bot's side, black-holed, deafened, taken offline, or fed a batch it already applied. A line only gets worse: a deaf line can be black-holed, but a black-holed line never hears again, because a real socket cannot lose frames and then deliver later ones. A night ends deterministically: once the room starts closing, each client bot closes a black-holed line, even while it waits for a reply, and leaves a deaf line for the client to drop as `Unanswered`. Some client bots deafen their line as the room closes to prove the client heals it alone. The night stops only when every client bot is live, has nothing pending, and sees the room closed. A client bot that cannot get there within `SETTLE_LIMIT_MS` fails the night. The checks trace every accepted client command to the batch in the log that `decide` reproduces for it, account for every sequence number in the client's activity, and compare the client's view at the end of each hand with `viewFor`, apart from clocks. A live batch is redacted for each viewer's audience after the batch. A catch-up redacts each missed event for the audience right after that event, from the states the host keeps for the last 201 events, because a seat can change hands between batches. `Welcome.catchUp` says what it covers: `UpToDate`, `Missed { from, events }`, or `Skipped { from, to }`, and the client checks the range instead of inferring it. A browser never sees the HTTP status of a refused upgrade, so a socket for a wrong code, a halted room, or a full room is accepted and closed with a `Closing` frame (`src/refused-socket.ts`). Only a wrong origin gets an HTTP refusal. A call from the Worker to a room can fail on Cloudflare, which refuses calls to a new Durable Object namespace for a while after its first deploy. That failure is a `RoomCallFailed` (`src/room-call-failed.ts`), logged with the room code and Cloudflare's reference and answered 503 `RoomUnavailable`, which a client may retry. Any other defect in a room route is logged as a `RouteFault` and answered 500 `ServerFault`, never an empty body. Each start of a room object logs one line with its instance and how many sockets it found, so the Worker's logs show when a room hibernated and woke. Every close the server makes goes through `closeWith` in `src/socket-close.ts`, and `test/close-paths.test.ts` fails on any other socket close. The object registers the exact ping and pong texts with the hibernation auto-response, so a ping never wakes a room, and it closes a live socket it has not heard from for `SOCKET_SILENCE_LIMIT_MS` with `Unresponsive`. After each commit the host counts the stored rows of the batch and halts if one is missing.
- `@nostakes/web` (`apps/web`): the browser app, a Foldkit program built with Vite. It talks to the server only through `@nostakes/client` and the three HTTP routes, and never imports `apps/room-server`. In development Vite proxies `/rooms` to the local room server, so the page and the server share one origin. Browser globals live in `src/client`; `src/features` holds the Model, the Messages, the pure update, and the views. The create and join screens build a player's face with `src/features/face-builder.ts`, and the room header reopens it as a sheet that sends `SetProfile`. The profile keeps the avatar as its code, and the device remembers it for the next room. A refusal reaches the update as the room's structured rejection, and `src/features/rejections.ts` turns it into a sentence with names from the current view. Its match is exhaustive over the room's and the table's rejections, and `test/rejections.test.ts` renders every rejection type with marked player ids, so a new rejection without a sentence, or a sentence that shows a raw id, fails. A view's clocks carry `at`, the server time the view was computed at, and each clock's `deadline` and full length `totalMs` in server time. The page keeps the differences between `at` and the local time of the last 8 updates, and counts each ring down to its `deadline` from the local time plus the largest difference, which comes from the quickest update. A late or repeated copy of a view therefore gives back no time. The tolerance is that quickest update's one-way delay, usually well under a second: a ring may end that much after the server's deadline, and never before it. Every colour, type size, spacing step, and radius lives in `src/client/tokens.css`. The link-preview tags come from `src/features/link-preview.ts`: a Vite plugin writes them into `index.html` and emits `invite.html` with the invitation text. `pnpm --filter @nostakes/web brand` regenerates `public/`: the favicon, the app icons, the preview card (`preview/card.png`, also the clip's poster), and the preview clip (`preview/clip.mp4`), which it records from the real table element in `scripts/brand/stage.html` in headless, muted Chromium and encodes with `ffmpeg`. Run it when the avatar art or the table's look changes, and commit what it writes.
- `@nostakes/fence` (`tools/fence`): fixture tests for the lint rules and the hook policy. It ships nothing.

## Commands

- `pnpm install`: install the workspace. `prepare` patches TypeScript and installs the git hooks.
- `pnpm dev`: run the room server on local workerd at `http://localhost:1337`, or the next free port when that one is taken, and the web app at `http://localhost:5173`. `apps/web/scripts/dev.ts` starts the server, reads the address it reports as ready, and points Vite's `/rooms` proxy there through `ROOM_SERVER_URL`. The server allows the origin in `ALLOWED_ORIGINS`, `http://localhost:5173` by default. It reads no Cloudflare credentials.
- `pnpm check`: lockfile check, strict typecheck, type-aware lint, and format check
- `pnpm test`: build each package and run every Vitest suite once
- `pnpm build`: compile each package to `dist`
- `pnpm typecheck`: strict effect-tsrs over every workspace and the root scripts
- `pnpm typecheck:tsc`: patched `tsc`. Run it when a checker pin changes.
- `pnpm typecheck:fast`: tsrs in seconds, without Effect diagnostics. `pnpm check` stays the gate.
- `pnpm lint`: type-aware lint and format check only
- `pnpm fix`: apply Oxfmt and safe Oxlint fixes. The fix deletes comment prose, so move what a comment knows into a name or a test first.
- `pnpm debt`: list every lint, Effect, and TypeScript directive with its reason. It exits non-zero while any directive exists. The list only shrinks.
- `pnpm verify`: run the long-running verification scripts of every package
- `pnpm smoke <base-url>`: play one hand against a running site, local or deployed. It asks again every 5 seconds, for up to 3 minutes, while opening the first room answers `RoomUnavailable`. CI runs it against the production Worker on local workerd.
- `pnpm plan:<stage>`: show what a deploy of `production` or `preview` would change. Add `--first` before the first deploy. It never writes to Cloudflare.
- `pnpm deploy:<stage> --confirm=<stage>`: check, test, build, deploy, and smoke the stage. Only the owner deploys. Agents never run it.
- `pnpm turbo run check test build`: the full gate. CI runs it after a frozen install.

### Verification scripts

A long-running check, such as an exhaustive enumeration or a simulator, is a script, not a test.

- Put it in `packages/<name>/scripts/<script>.ts`. The package tsconfig already includes `scripts/`, so the fence checks it.
- Add `"verify": "node scripts/<script>.ts"` to the package `scripts`. Node strips the types. Chain several scripts with `&&`.
- Import the package by its own name, for example `@nostakes/engine`. The name resolves to the built `dist`, and turbo's `verify` task builds the package first.
- Print with Effect `Console`, run the program with `Effect.runPromise`, and fail the Effect on a counterexample. A failed Effect exits non-zero.
- `verify` is not part of `check` or `test`, and turbo never caches it. Run `pnpm verify` before you commit a change to the rules a script covers.
- `apps/room-server` is the exception. Its probes need a deployed Worker, and only the `@alchemy.run/test` harness deploys one to local workerd, so its `verify` runs `scripts/*.verify.ts` through `vitest.verify.config.ts`. Each probe fails its Effect with a tagged error on a counterexample. `scripts/soak.verify.ts` plays at least 1,000 hands across at least 10 rooms, seven in ten of them checked, and its summary counts the bots' fair-shuffle verdicts by kind and the wait beyond the pause before each sealed deal. Set `SOAK_SEED`, `SOAK_HANDS`, and `SOAK_ROOMS` to replay or resize it. A failed room prints its seed and code and saves its stored log to a temporary directory, with a timeline beside it: the night's own steps and, for each client bot, its connection phases, its lines, every frame it sent, swallowed, or got, and each command with its outcome. Set `SOAK_KEEP_LOGS=true` to save every room's log and timeline. `scripts/hibernation.verify.ts` pings through a 30-second idle and checks the room still hibernates. `scripts/silence.verify.ts` waits about 60 seconds for a quiet socket to be closed as `Unresponsive` while a pinging one stays.
- `apps/web` runs `scripts/two-players.ts` as its `verify`. It starts the room server through `alchemy dev` and the web app through Vite on port 5199, then two headless Chromium windows launched with `--mute-audio` open a room, join, sit, start, and play a hand until a pot is awarded. CI installs the headless shell first with `playwright-core install --with-deps --only-shell chromium`. Every automated browser in this repo is headless and muted.
- Integration tests that start workerd cost seconds on every commit through the hook. Keep `pnpm test` for the room server under about 30 seconds: one `beforeAll(deploy(ToyStack))` per file, files in parallel workers, and slow probes such as the hibernation idle and the 60-second silence limit in `verify`.

## Fence

The fence makes cheating uncomfortable. If a hook fails, fix the failure. Do not disable the fence.

- Lefthook pre-commit runs `pnpm check` and `pnpm test`.
- Never skip the hooks: no `--no-verify`, no `commit -n`, no `LEFTHOOK=0`, no `core.hooksPath` override. The Claude Code hook in `.claude/settings.json` denies these commands. The policy lives in `scripts/vcs-command-policy.js`.
- `tsconfig.base.json` owns the Effect diagnostic severities. A package tsconfig may add an exact `allowedUnstableApis` entry only for a module the checker warns about. `engine` and `ledger` already allow `@effect/vitest` and `effect/Arbitrary`, because every test needs them. `apps/room-server` also allows the `effect/http` modules it uses, and `effect/FileSystem` and `@effect/platform-node/NodeFileSystem` for the soak's saved logs.
- Some rules collide with common Effect forms. Use the form that passes both:
  - `unicorn/no-array-method-this-argument` reads any two-argument `.map`, `.filter`, or `.forEach` as an array call with `thisArg`. `Option.map(option, f)` and `Effect.forEach(items, f)` trip it. Write `option.pipe(Option.map(f))` and `pipe(items, Effect.forEach(f))`. `Effect.forEach(f, { concurrency })` trips it too, so write `Effect.all(items.map(f), { concurrency })`.
  - `anti-slop-effect/no-service-constructor-imports` rejects importing any `make<Name>` outside a test file. Name a factory for what it returns, such as `hostRoom` or `roomObject`.
  - `no-empty-object-type` rejects an empty `Data.TaggedEnum` variant. Give every variant a field that says something.
  - `anti-slop-effect/no-manual-tagged-construction` rejects a `_tag` in an object literal, test fixtures included. Compare wire frames as JSON text when a test needs the literal form.
  - The Effect diagnostic `missingReturnYieldStar` wants `return yield*` on an Effect that never succeeds, and `consistent-return` rejects a generator that mixes `return;` with `return yield* ...`. Collect the outcome in a variable, leave the loop, and end with one `return yield* Option.match(outcome, { onNone: () => Effect.void, onSome: (problem) => Effect.fail(...) })`.
  - `promise/prefer-await-to-then` reads `Effect.catch` as a promise `.catch`, and `promise/prefer-await-to-callbacks` reads a callback whose parameter is named `error` as a Node callback. Use `Effect.mapError` or `Effect.catchTag`, and name the parameter `failure`.
  - `anti-slop/no-shape-in-symbol-names` rejects any name containing "shape". Name the thing for what it holds, such as `recipe` or `plan`.
  - A room view or rejection holds `Option` values, which plain `JSON.stringify` cannot carry. Wrap a core's schemas in `Schema.toCodecJson` before `Schema.fromJsonString`. `HostedRoom` and `ClientSchemas` take a `WireCodec`, whose encoded side is `Schema.Json`, so a schema that skips this does not typecheck.
  - `typescript/no-unsafe-type-assertion` rejects a narrowing assertion even with a `SAFETY:` comment. Narrow with a type predicate instead, as `src/workerd.ts` does for the globals only workerd defines.
  - A type-level test uses `expectTypeOf` from `@effect/vitest`, not `@ts-expect-error`, because every directive counts as debt.
- `no-redeclare` rejects Foldkit's habit of naming a schema and its type alike (`const Model` beside `type Model`). Name the schema `ModelSchema` and the Message union `Messages`, and keep `Model` and `Message` for the types.
- `xstate-effect/no-inline-effect` rejects an Effect returned from an inline `enq` callback and inline Effect logic passed to `enq.spawn`. Declare Effect work in `setupEffect({ actors })`.
- CI runs `pnpm install --frozen-lockfile` and then `pnpm turbo run check test build`.

## Project law

- Chips are integers. No floating point anywhere near a chip amount. Model amounts with an integer Schema. Never divide chips with `/`, and never repair a result with `Math.round`. Every split names its rule for the remainder.
- Pure domain packages (`engine`, `ledger`) do no I/O and read no clock or randomness. Inputs such as the shuffled deck arrive as data. The Effect diagnostics `globalDate`, `globalRandom`, `globalTimers`, `globalConsole`, `globalFetch`, `cryptoRandomUUID`, and `nodeBuiltinImport` are errors, and `nostakes-patterns/no-module-level-mutable-state` bans module-level `let` and `var`.
- Errors are part of the interface. Define each one as a `Schema.TaggedError`, for example `class SeatTaken extends Schema.TaggedError<SeatTaken>()("SeatTaken", { seat: Schema.Int }) {}`. Name the failure, keep its context, and say how to fix it.
- Schemas are the contract. Parse unknown input with Effect `Schema` at the boundary. Trust internal types after that. Do not validate the same value twice.
- No comments in code. `no-comments/no-comments` bans them. Agents copy comments, and a comment that explains a workaround spreads the workaround. Say it in a name, a type, a test, or the commit message. Three kinds survive:
  - A tool directive with its reason after `--`: `// oxlint-disable-next-line <rule> -- <reason>`, `// @effect-diagnostics-next-line <rule>:off -- <reason>`, or `// @ts-expect-error -- <reason>`
  - A one-line `SAFETY:` comment above a type assertion that names the invariant it relies on
  - A JSDoc block made only of type tags in a plain JS file
- Credit for borrowed code lives in `PROVENANCE.md`.
- Tests prove behaviour. Write Effect tests with `it.effect` and `it.layer` from `@effect/vitest`. `Effect.run*` and `ManagedRuntime.make` in a test file fail lint.
- Prefer properties and models. A domain rule is an `it.prop` or `it.effect.prop` over Schema or `effect/Arbitrary` inputs. Anything with history, such as a hand or a session, is a model checked over generated command sequences. Keep example tests for seams.
- Plant a bug before you trust a new test. The test must fail, then pass once you restore the code. Tautological tests and change-detector tests are harmful.
- Delete `passWithNoTests` from a package's `vitest.config.ts` when its first test lands.
- Lint baselines only shrink. Add a lint rule before you clean up a bad pattern.

## Architecture

- Dependencies run from `apps` to `packages`. `nostakes-boundaries/no-cross-layer-imports` stops a package from importing app code.
- `engine` owns the rules of a hand. `ledger` owns the money across a session. Neither imports the other yet.
- Pure domain state machines are plain reducers over tagged unions. `decide(state, command)` returns the events the command causes, or fails with a tagged error. `evolve(state, event)` returns the next state. Branch with `Match.tagsExhaustive` or a `Data.taggedEnum` `$match`. A `switch` on `_tag` fails lint (`anti-slop-effect/no-manual-tag-comparison`).
- `protocol` owns the wire, including the close reasons and their codes, the ping and pong texts, the ping interval, and the server's silence limit. `room-server` owns identity, storage, delivery, and limits, and depends on `protocol`. The pure room core plugs into the server through `HostedRoom` in one module and never sees a socket, a token, or a sequence number.
- Lifecycles with side effects are XState machines. This is a deliberate reading of rat-stack's "lifecycles are machines" rule. A pure reducer has no side effect to retry, cancel, or resume, so it needs no actor. A lifecycle that waits, times out, or talks to the network gets a machine.
- The room server has no XState machine. Its only lifecycle is "wait until a deadline, then act", and that deadline is data in the core's state (`nextDeadline`), re-read on every start and after every commit and armed as the Durable Object alarm. There is no hidden state for a machine to own. Every change to a room goes through one synchronous commit function in `src/room-host.ts` that cannot await.
- The client's connection lifecycle has hidden state and side effects, so it is one XState machine, `roomClientMachine` in `packages/client/src/machine.ts`. XState owns the states (Idle, Connecting, Greeting, Live, Waiting, Refused, Stopped) and which transitions are legal. Declared Effect actors own the work. The Online state invokes the connection actor, so the socket lives exactly as long as Online. Time, backoff jitter, and the socket are the Effect services `Clock`, `Random`, and `Transport`, each with a live and a test layer. The embedding app sends `wake` when the page becomes visible or the network returns.
- Arm a machine timer as a named delayed event with an id, and cancel it on exit. XState's built-in `xstate.after` and `xstate.done.actor` events are not in a machine's event type, so a pure model test could only fire them through an unsafe cast. For the same reason a child actor relays named events to its parent instead of finishing with output.
- `Effect.sleep` inside a loop fails lint (`nostakes-patterns/no-sleep-in-loop`). Waiting belongs in a machine.

## Source control

- Trunk-based development. Commit small atomic changes straight to `main`. Every commit passes `pnpm check` and `pnpm test` through the hook.
- Use a conventional prefix (`feat:`, `fix:`, `test:`, `build:`, `ci:`, `docs:`, `chore:`) and an imperative subject under 72 characters. Add a body when the why is not obvious.
- Stage only the files your change touched. Never commit `dist`, `.turbo`, or secrets.

## Boundaries and sign-off

- Safe by default: code and tests inside a package, a new or tighter test or lint rule, a targeted override with a written reason, an `allowedUnstableApis` entry the checker asks for, a new verification script, and edits to `AGENTS.md` and `README.md`.
- Needs owner sign-off: adding, removing, or bumping any dependency, because pins are exact and CI installs cold. Any edit that loosens `oxlint.config.ts`, the diagnostics in `tsconfig.base.json`, `lefthook.yml`, `.claude/settings.json`, or `scripts/vcs-command-policy.js`. A new package or app. Anything that brings I/O, a clock, or randomness into `engine` or `ledger`.
